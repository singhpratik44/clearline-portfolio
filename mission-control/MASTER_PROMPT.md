# APERTURE / CAUSAL LOOM — MASTER BUILD PROMPT v3
Build a commercially credible, radically original meeting and project operating system that turns communication into accountable, verified execution, without a dashboard maze.

## North star
A meeting is not a transcript. It is a transition in a causal graph: EVIDENCE → DECISION PROPOSAL → HUMAN REVIEW → AUTHORIZED COMMITMENT → TASK → DEPENDENCY → MEASURED OUTCOME. Every transition retains who, when, source, proposed effects, and reversibility.

## Interface challenge: make a new visual grammar
Invent a responsive, legible **Causal Loom**: multiple project timelines as orbiting threads; meetings as temporal portals; unapproved decisions as translucent pulses; blocked tasks as tension knots; fulfilled work as luminous resolved paths. Interaction must be useful, not decoration. Users can scrub time, filter projects, select nodes, inspect why a dependency exists, and change one proposal with visible downstream effects. Every visual needs a text/keyboard equivalent. Low motion, 60fps budget and mobile are not optional.

## Scope
1. Meetings: agenda preparation, decisions, owners, action proposals, source notes, pre-meeting checklist, local calendar event file, and a private meeting trail.
2. Projects: scoped initiatives, task owner, due date, explicit dependencies, priority, status, readiness calculation, and blockers.
3. Causality: a deterministic typed DAG with cycle checks; a completed predecessor unlocks dependent work. Show due/blocked/ready, but never fabricate an estimated completion date.
4. Governance: proposals are never tasks until a human approves them. Approval is not an email send, payment, contract or external execution.
5. Evidence: each decision links to its source meeting, notes and approval event. Treat transcripts as untrusted inputs, never auto-adopt invented statements.
6. Data: user-specific data remains private. Static GitHub Pages may contain only synthetic demo content. Local export/import, optional encrypted browser vault, never publish Gmail/Calendar or meeting content in the repo.
7. Automation: deterministic detection first; any LLM/meeting recording/transcription is opt-in, correctly scoped, consent-aware, subject to provider and organizational policy.
8. Commercial use: create tiny workflows—Meeting Action Ledger, Follow-Up Radar, Blocker Cascade, Weekly Portfolio Brief, and Decision Provenance—with clear target metric and specific service pages.
9. Research: review ten recent, primary-source studies. Include dates, versions when available, publication/review status, measured limitations, hypotheses and tests. Source discovery from arXiv, OpenReview, NeurIPS/ICML, AutoML, LangChain, Hugging Face Papers, Papers with Code and MLPapersWeekly. Do not claim feeds auto-connected unless verified.
10. Engineering: preserve existing APERTURE sites; standalone static GitHub Pages site; deterministic tests and automated deploy and public HTTP verification; no credentials in repo.

## Build order
A. Working meeting/project schema + constraints.
B. Radically original but accessible animated Causal Loom.
C. Functional create meeting, create project, capture decision proposal, approve action, create tasks, dependencies, complete/reopen, audit timeline.
D. Source-linked research observatory.
E. Local encrypted data and import/export.
F. Mobile + desktop browser smoke tests, CI release stamp, deploy verification.
G. Integrations only after secure OAuth/backend design is approved.

## Measurable acceptance
A user can create a project and meeting, make an evidence-supported proposed decision, explicitly approve it, see a linked task, see blockers and unlocks, and export/re-import an identical private snapshot. A failed dependency cycle is rejected. No external action can occur; no personal data in GitHub. The site is reachable at its release URL and all tests pass.

## Definition of ready
This release is a private-first pilot with synthetic demonstration, not a production collaboration backend. Provide the exact gaps for live Google Calendar/Meet, Zoom, Teams, Slack, Asana, Linear, or other integrations. Every future integration requires scopes, consent, idempotency, privacy controls and human-approved write gates.
