# CODE THE GAME — Executable prompt sequence

These prompts are ordered by customer risk and commercial value. Execute each with source inspection, reversible commits, deterministic tests, and evidence; do not claim completion from planning alone.

Inspect the current catalog and product pages. Ensure every product has an accurate detail page, pricing, required software, honest digital format, free sample link, correct existing Stripe Payment Link, and transparent delivery and refund information. Preserve other APERTURE sites. Test product links and build artifact.

## Prompt B — Privacy and trust
Inspect actual data flows before drafting claims. Document local browser progress, private URL-fragment keys, GitHub Pages hosting, Stripe-hosted payment processing, support email handling and limits on account recovery. Link notice from the store. Do not invent GDPR/COPPA compliance or legal guarantees. Escalate jurisdiction-specific legal questions.

**Current implementation:** Static privacy notice and catalog navigation link. No independent legal audit.

## Prompt C — Checkout-to-course verification
Inspect Stripe Payment Link after-payment redirects using authorized read-only Stripe tools. Map each link to the correct encrypted course pack. Verify no keys are in public source. Create a deterministic mock of the client-side reader flow using nonproduction fixtures, without printing bearer secrets. Record real-payment verification as blocked until an explicitly approved charge or supported safe test mode is available. Do not create a real charge automatically.

## Prompt D — Engine-specific quality audit
Audit all 20 written lessons and sample code against their stated Roblox Studio, Minecraft Education MakeCode, and Godot 4 prerequisites. Run syntax and structural checks first. Execute code in the actual target engine only when an engine is available; otherwise mark as unverified and do not invent screenshots. Prepare original project preview assets only from genuine outputs.

## Prompt E — Conversion measurement and launch
Add privacy-conscious, consent-reviewed checkout click instrumentation without collecting access keys or student identifiers. Distinguish visits, checkout clicks, paid orders, refunds and confirmed lesson delivery. Draft organic channel-specific launch assets. Never send unsolicited bulk email, launch ads, or spend money without approval.

## Mandatory release report
For each run return changed files, commit SHA, test and deployment status, public URLs, independently verified behaviors, blocked checks, and next executable step. Never substitute source-code inspection for payment-delivery evidence.
