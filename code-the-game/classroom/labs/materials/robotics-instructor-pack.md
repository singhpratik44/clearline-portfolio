# Robotics Mission Instructor Pack — CODE THE GAME

Independent classroom resource · Version 1 · 4 lessons × 45–60 minutes

## Instructor overview
Ages approximately 10–14, adjust to learner needs. Browser-only simulation; physical LEGO hardware not required. No affiliation with LEGO Education or FIRST. Outcomes are proposed, not independently evaluated.

### Session 1 — Sequencing and orientation
**Learning goal:** Predict where a robot will move after a command sequence.
**Warm-up:** On a 6×6 paper grid, draw the robot at (column 1, row 6), facing east. What happens after Forward, Forward, Left, Forward?
**Lab:** Complete Mission 1. Predict first, then run. Record each command.
**Evidence:** Algorithm, prediction, result, one revision.
**Exit ticket:** Explain the difference between a turn and a move.

### Session 2 — Debugging and obstacles
**Learning goal:** Find and fix an incorrect step without randomly changing everything.
**Lab:** Complete Mission 2. Run one unsuccessful attempt deliberately, identify the first failed step, revise one command.
**Partner task:** One student writes the algorithm, another traces it on paper.
**Evidence:** Before/after programs and a clear cause of failure.
**Exit ticket:** Why is reproducible testing useful?

### Session 3 — Constraints and path planning
**Learning goal:** Represent obstacles and plan around constraints.
**Lab:** Complete Mission 3. Sketch two routes before coding.
**Discussion:** Shortest route versus simplest program; why might these differ?
**Evidence:** Two sketches, chosen route, execution result.

### Session 4 — Optimize and communicate
**Learning goal:** Compare successful algorithms using command count.
**Lab:** Complete Mission 4. Find a working solution, then attempt a shorter one.
**Evidence:** First working program, improved program, command counts and reasoning.
**Extension:** Explain how physical motors, sensors and battery limits complicate simulation.

## Teacher quick-check key
- A left or right turn changes direction without changing position.
- Forward changes position by exactly one grid square.
- A collision or move outside the grid stops the run.
- A valid solution must reach the goal without hitting obstacles.
- More commands do not necessarily mean a more reliable solution on physical hardware.

## Assessment (0–3 per criterion, /12)
Algorithm correctness · Debugging evidence · Explanation · Teamwork/accessibility.
0 missing; 1 partial; 2 correct with evidence; 3 correct, reproducible and thoughtfully revised.

## Access and safeguarding
Use anonymous team codes rather than names in exported files. Teacher reviews device access, accommodations and safety. Any physical LEGO extension requires separately approved kits, instruction and procurement. No student account is needed for the browser lab.
