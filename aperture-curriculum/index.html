Iteration 1 · Build the first teachable sequence

Five projects, one progression

Each project ends with a working artifact, a short explanation, peer feedback, and one revision. The goal is transfer: learners carry ideas from visual logic into apps, data, and physical systems.

Project 1 · Scratch

Game with a rule

Challenge: create a playable sports or community game with a clear win condition.

Skills: events, sequence, loops, conditionals, variables, storytelling.

Evidence: playable build, rule card, 60-second explanation, one tested revision.

Project 2 · MakeCode Arcade

Build the next version

Challenge: rebuild the game with collision, scoring, levels, and a debugging log.

Skills: state, variables, functions, iteration, testing, debugging.

Evidence: playable release, bug log, test cases, peer playtest changes.

Project 3 · Python

Answer a real question

Challenge: use a small dataset to answer a sports, school, or community question.

Skills: data types, loops, functions, basic statistics, visualization, assumptions.

Evidence: runnable notebook or script, chart, claim, limitations, revised conclusion.

Project 4 · MIT App Inventor

Make a useful app

Challenge: prototype a habit tracker, team tool, or community helper for a named user.

Skills: user story, screens, events, data flow, testing, accessible design.

Evidence: clickable prototype, user test notes, prioritized fixes, demo video or live walkthrough.

Project 5 · Tinkercad

Design a system

Challenge: model an object or simulate a circuit that responds to a real need.

Skills: constraints, measurement, components, simulation, iteration, explanation.

Evidence: model or circuit, design brief, test result, failure analysis, improved version.

Shared capstone

Project showcase

Learners choose one project to improve for a real audience. They present the problem, design choices, test evidence, revision, and next step.

Common rubric: problem framing 20% · computational thinking 20% · working artifact 20% · testing and revision 20% · explanation and care for the user 20%.

Facilitator kit · starter files

Start quickly, then make it yours

Each starter keeps the first ten minutes focused on the learning goal. Learners still choose the theme, rules, data, user, or design constraint.

Scratch · Game with a rule

Starter: player sprite, opponent sprite, score variable, start event, and one unfinished rule.

Facilitator prompt: What must be true for a player to win? What should happen when the rule is broken?

Extension: add a second level or a fairness change.

MakeCode · Build the next version

Starter: arcade scene, player movement, collision event, score variable, and one seeded bug.

Facilitator prompt: What test would reveal the bug? What evidence shows the fix works?

Extension: add levels, difficulty, or a replayable challenge.

Python · Answer a real question

Starter: small CSV dataset, loading cell, one example calculation, and a blank claim box.

Facilitator prompt: What does the data measure? What cannot it tell us?

Extension: compare two groups or run a simple simulation.

App Inventor · Make a useful app

Starter: two screens, one input, one button event, and a result label.

Facilitator prompt: Who is the user and what is the smallest useful action?

Extension: add persistence, accessibility options, or a second user test.

Tinkercad · Design a system

Starter: constrained workspace, component palette, wiring example, and one measurable target.

Facilitator prompt: What constraint matters most: cost, size, safety, speed, or reliability?

Extension: introduce a failure condition and redesign around it.

Showcase · Evidence sheet

Starter: problem, artifact link, test result, revision, and next step fields.

Extension: add a 60-second demo, peer quote, and portfolio reflection.

Facilitator kit · troubleshooting cards

When a learner is stuck

Nothing runs

Check the start event, file type, selected device, and whether the learner saved the latest version. Ask the learner to explain the expected first action before changing code.

The learner copied the example

Ask them to change one rule, input, user, or constraint. Score the explanation and revision rather than visual complexity.

The project is too large

Cut to one user, one core action, and one test. Move extra ideas into an extension list for later.

The learner cannot explain the code

Have them trace one input through one decision to one output. Use a diagram or spoken explanation before asking for more code.

Data gives a surprising result

Check the sample size, labels, missing values, and comparison rule. Treat the surprise as a question to investigate.

Hardware or simulator fails

Separate wiring or setup from the concept. Reproduce the smallest circuit, change one component at a time, and record the failed test.

Different skill levels

Keep the same outcome and rubric. Offer a guided starter, standard path, and extension path so learners can work at different depths.

Time is running out

Stop adding features. Capture the current artifact, one test result, one revision idea, and a short explanation for the showcase.
